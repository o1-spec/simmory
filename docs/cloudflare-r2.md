# Cloudflare R2 Media Storage Guide — Simmory

This guide documents the setup, configuration, security posture, and CORS policies for storing private family cooking recordings in Cloudflare R2 (or any S3-compatible object storage provider) for Simmory.

---

## 1. Overview & Security Architecture

Simmory uses **direct browser-to-bucket presigned uploads** with server-side integrity verification:

```
[Browser] 
   │  1. POST /api/videos/initiate (metadata, size, MIME)
   ▼
[Next.js Server] ── Checks Kitchen Membership & Generates Presigned PUT URL (5m)
   │  2. Returns uploadUrl & storageKey
   ▼
[Browser] ── Direct PUT Upload with XMLHttpProgress ──▶ [Cloudflare R2 Bucket]
   │  3. POST /api/videos/[id]/complete
   ▼
[Next.js Server] ── S3 HEAD Object Verification ──────▶ [Cloudflare R2 Bucket]
   │  4. Confirms size & marks UPLOADED in PostgreSQL
   ▼
[Family Cook] ── Plays video via 15-minute temporary signed GET token
```

### Key Security Guardrails:
- **Zero Public Access:** The R2 bucket is strictly private. Public URL access, R2 dev subdomains, and public bucket policies are **disabled**.
- **No Client Secrets:** R2 access keys and secret tokens never touch client browser code.
- **Short-Lived Bearer URLs:** Presigned PUT URLs expire in 5 minutes; playback GET URLs expire in 15 minutes.
- **Independent Server Verification:** The application never trusts client claims of upload success; it executes an independent `HeadObjectCommand` to verify bytes stored before marking records as `UPLOADED`.
- **Anti-IDOR Multi-Tenant Isolation:** All video operations check kitchen membership. Members cannot probe or stream other families' cooking videos.

## 2. Step-by-Step Cloudflare R2 Setup

### Step 1: Create the Bucket
1. Log in to the [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. In the left navigation, select **R2 Storage** > **Overview**.
3. Click **Create bucket**.
4. Enter a bucket name (e.g., `simmory-videos-production` or `simmory-videos-dev`).
5. Set **Location** to **Automatic** (or select your preferred geographical region).
6. Click **Create bucket**.

### Step 2: Keep the Bucket Strictly Private
1. Inside your bucket settings in Cloudflare, navigate to the **Settings** tab.
2. Under **Public Access**:
   - Ensure **R2.dev subdomain** is **Disabled**.
   - Ensure **Custom Domains** are **Not Configured** (or restricted behind Cloudflare Access).
3. Do not attach any public read policies. All access must flow through signed URLs generated by Simmory's server layer.

### Step 3: Create API Credentials (Principle of Least Privilege)
1. In Cloudflare Dashboard, go to **R2 Storage** > **Overview**.
2. Click **Manage R2 API Tokens** on the right side.
3. Click **Create API token**.
4. Configure token permissions:
   - **Token Name:** `simmory-web-production`
   - **Permissions:** Choose **Object Read & Write**.
   - **Specify bucket(s):** Select **Apply to specific buckets only** and pick your `simmory-videos-...` bucket.
   - **TTL / Expiration:** Set an appropriate rotation schedule (e.g. 1 year).
5. Click **Create API Token**.
6. Cloudflare will display:
   - **Access Key ID** (e.g., 32-character hexadecimal string)
   - **Secret Access Key** (e.g., 64-character hexadecimal string)
   - **Endpoint** (format: `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`)
7. Store these values securely in your production secrets manager. **Never commit them to git.**

## 3. Environment Variables Configuration

Add the following variables to `.env` (development) or your hosting deployment settings (Vercel, Render, AWS):

```env
# Cloudflare R2 / S3-Compatible Object Storage
R2_ACCOUNT_ID="your_cloudflare_account_id"
R2_ACCESS_KEY_ID="your_r2_access_key_id"
R2_SECRET_ACCESS_KEY="your_r2_secret_access_key"
R2_BUCKET_NAME="simmory-videos-dev"

# Optional: Custom S3 endpoint (defaults to Cloudflare R2 format if omitted)
# R2_ENDPOINT="https://<ACCOUNT_ID>.r2.cloudflarestorage.com"

# Optional: Configurable upload file size limit in MB (default: 250MB)
MAX_VIDEO_SIZE_MB="250"
```

> [!IMPORTANT]
> Do NOT prefix any storage variable with `NEXT_PUBLIC_`. All S3 client operations and signing must remain strictly server-side.

## 4. CORS (Cross-Origin Resource Sharing) Configuration

Because browsers perform direct `PUT` uploads to Cloudflare R2, the bucket must accept preflight `OPTIONS` requests from your application origin.

### Setting CORS in the Cloudflare Dashboard:
1. In the Cloudflare Dashboard, open your bucket and navigate to **Settings** > **CORS Policy**.
2. Add the following JSON policy:

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:3000",
      "https://simmory.app",
      "https://*.simmory.app"
    ],
    "AllowedMethods": [
      "GET",
      "PUT",
      "HEAD"
    ],
    "AllowedHeaders": [
      "Content-Type",
      "Content-Length"
    ],
    "ExposeHeaders": [
      "ETag"
    ],
    "MaxAgeSeconds": 3600
  }
]
```

## 5. Testing & Verification

### Local Development Smoke Test (Without Cloud Credentials)
- When R2 credentials are not set or left as template placeholders, the application runs normally without crashes.
- The `/upload` page displays a notification: *"Cloudflare R2 Storage Setup Pending"*.
- Initiating an upload returns `503 Storage not configured`.
- All automated unit and integration tests run against mocked storage boundaries with 100% test pass rate.

### Live Production Verification (With Real Credentials)
1. Add valid credentials to `.env`.
2. Start the development server (`npm run dev`) and sign in.
3. Open `/upload`.
4. Select a family kitchen, choose a short cooking test video (`.mp4`), and click **Upload Video**.
5. Observe real-time percentage progress bar via browser `XMLHttpRequest` events.
6. Once upload completes, verify that the server marks the video `UPLOADED`.
7. Navigate to the video detail page (`/videos/[id]`) and play the video using the temporary signed stream URL.
8. In the Cloudflare Dashboard, navigate to your bucket's **Objects** tab:
   - Confirm that the object key exists under `kitchens/<kitchenId>/videos/<uuid>-<filename>.mp4`.
   - Confirm file size matches the uploaded asset.

## 7. Common Upload Errors & Troubleshooting

| Symptom / Error | Cause | Remediation |
| :--- | :--- | :--- |
| **503 Storage not configured** | Missing or template R2 credentials in environment | Add valid `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `R2_BUCKET_NAME` to `.env`. |
| **CORS Network Error on PUT** | Bucket CORS policy does not list current origin | Update CORS policy in Cloudflare bucket settings to include your current domain or `http://localhost:3000`. |
| **403 Forbidden on PUT** | Expired signed URL or invalid token permissions | Presigned upload URLs expire after 5 minutes. Verify that the R2 API token has Object Read & Write permission. |
| **Upload Integrity Verification Failed** | R2 HEAD request could not locate object | The direct browser upload was interrupted or aborted before the server finalized the record. Click "Retry Upload". |
| **Playback Stream Expired** | 15-minute signed URL token expired | Click "Renew stream token" below the video player to obtain a fresh temporary URL. |
